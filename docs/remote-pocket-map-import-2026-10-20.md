# 已存在子地图导入与未打开入口（2026-10-20）

本次接续 `remote-pocket-maps-2026-10-20.md` 的生命周期恢复，补齐已有子地图导入。按用户进一步澄清，**进入对应子地图时加载，打开远程主地图时不预加载**。只修改 1.7；1.6 保持冻结。

## 行为

| 防守方入口状态 | 进攻方行为 |
| --- | --- |
| 已有子地图，包括嵌套地图 | 打开远程主地图时仅保留待加载快照。单位进入对应入口时只还原该层地图，再登记到原版地图列表；嵌套地图继续等待进入其入口。保留原内容、入口/出口及父子关系，重复进入复用同一地图。 |
| 未打开的原版 Anomaly 深坑 | 满足原版稳定期等条件后，在进攻方本地调用原版生成器；同一来源地图只允许一个深坑，匹配原版生成器对来源入口的假设。 |
| 未打开的原版 Odyssey 古代地堡 | 保留破解/封锁条件；允许原版 AncientStockpile 生成器及默认、AncientStockpile、AncientStockpileFake 布局，使用合法原版 stockpile 枚举。 |
| 其他未验证入口、生成器或布局 | 禁止进入和触发生成，显示本地化原因。防守方已有地图时则使用已导入内容。 |

新生成地图只属于本次远程会话，不替防守方创建地图、解锁入口或推进任务。关闭会话时与导入的后代地图一同清理；玩家自己的本地子地图不受影响。

## 共用机制与修正

- 复用 `SavePocketMapTree` 确定后代，`RemoteMapProjectionTree` 一次分配并替换全树 ID，再按地图拆分。未访问地图和父对象均不登记到游戏，不参与模拟或地图列表。
- `RemoteMapDeferredPockets` 由会话父对象持有并随存档保存待加载 XML、后处理元数据及所需的已加载对象引用。首次进入通过统一的 `RemoteMapRuntimeLoader` 还原单层，连接原入口与出口；失败保留快照重试，不退回重新生成。
- 在 Scribe 的 PostLoadInit 之前登记本次加载的地图及父对象，遵循原版 Game 读档顺序。尚未进入的前向入口链接留空，实际加载后才连接，避免指向不存在的地图。
- 所有地图共用已有阵营映射、单位引用、运行状态清理和第三方兼容入口。战术后处理在每层实际加载时执行，子地图不再覆盖主地图的防御点隐藏记录。
- 物品/单位原始身份按各自来源地图登记，子地图销毁时移除对应身份；沿用既有结算与清理入口。
- 布局结构和房间全局 ID 一并重写，保留房间局部编号和相互引用。分配时推进原版计数器；避开原版会随机替换的房间 ID 0，防止后续原版生成/读档出现重号。
- 导入任务信号统一添加会话命名空间，保留同一投影内部的发送者/接收者对应，清除外部 `Quest_N` 引用；不导入防守方 QuestManager。生成器异常后恢复原版 `currentlyGeneratingPortal` 上下文。
- 原版死亡单位处于 Destroyed 状态，但不等于 Discarded；尸体仍以引用方式保存其单位。修正引用单位保留/清理条件，使死亡单位随存档保存，在会话关闭后正常释放；新生成尸体的内部单位也登记同一清理归属。
- 原有世界单位关系展开预算不再截断地图树的直接引用；300 个直接尸体单位引用的单元用例确认全部保留。

## 定向验证

配置 `Tools/RimTestPocketMaps.json`，双客户端、Anomaly + Odyssey、en-US / fr-FR。复用原有 18 步前置及专项场景，没有运行全量矩阵。

专项内容：

1. 防守方真实生成深坑及其内嵌 Gravcore 地堡，保留两件具有特定耐久和位置的武器作为内容标记。进攻方打开主地图后断言没有远程子地图；首次进入深坑只出现一层，进入地堡再出现第二层。比较内容及入口连接，证明还原原地图而非重新生成。
2. 通过原版 QuestUtility 生成两个 Gravcore 任务及地表任务地图，确认任务从 Ongoing 到 EndedSuccess，并得到真实/假地堡入口。已有地堡和仍锁定的未进入入口同时存在。
3. 进攻方独立生成假地堡、真实 Gravcore 地堡和嵌套深坑；检查真实地堡的 Gravcore、布局/房间引用、未知布局拒绝及原版锁定条件。
4. 本地与投影设置同名信号对照，破解投影入口只触发投影接收者。
5. 攻击者在未进入任何子地图时保存/读档，仍保持待加载；从原版菜单进入已有深坑和内嵌地堡、返回并重复进入，检查无重复加载。进入新生成地堡后再次保存/读档，对比尸体及内部死亡单位身份，从子地图结束袭击，检查地图归属、真实攻击者清理豁免及无地图/临时 world pawn 遗留。观察会话另覆盖完全不进入子地图便关闭。
6. 观察关闭和袭击结算重连后比较防守方的子地图内容、单位身份、入口目标/出口/破解状态、任务状态和测试信件，验证本地生成及信号没有回写到防守方。仅放行原版普通读档将 LayoutRoom ID 0 迁为随机 ID 的变化，其余字段严格比较。

夹具边界：真实任务入口生成后移至测试殖民地/已有深坑，方便既有多人地图标记选择；深坑设为原版稳定期之后、首次涌出后的冷却状态。往返专项对远程非玩家单位施加原版临时眩晕，避免单个测试旅行者在抵达入口之前被守军击倒。没有瞬移玩家或替代原版转图任务。本专项不证明战斗平衡、随机交战存活率、所有战利品枚举组合或第三方生成器稳定性。

单元测试覆盖图复制不修改源数据、重叠 ID、嵌套关系、信号配对/隔离、布局 ID 及计数器、逐地图身份登记/清理、防御点隐藏累积，并定向复查远程关闭、支援损失与兼容入口。
