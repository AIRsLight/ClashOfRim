# 游戏和模组更新后的兼容性入服锁死

## 现象与根因

用户报告 RimWorld 本体和一个模组更新后，主菜单入服只提示套用服务器配置，管理员覆盖入口缺失。文件更新无法通过套用配置还原，因而无法继续登录。

新增测试分别复现了两个缺陷：

1. `WorldSessionPreparation.Reject` 保留了兼容性差异和服务端清单，却漏传握手结果中的 `CanOverrideCompatibilityBaseline`。主菜单走世界准备接口，因此即使凭据已验证且账号为管理员，客户端也收到默认 false。地图登录接口原本会传递该字段。
2. `ClientCompatibilityReport` 用“清单页存在差异”判断是否可以套用模组列表。清单页还包含 RimWorld 版本、清单格式版本及未知问题，这些都不是模组启用状态或加载顺序，重启套用不能修复。

此前测试只验证纯文件差异不提供套用按钮；修复操作的测试夹具还以清单格式版本差异触发套用，恰好掩盖了第二个问题。夹具现改为真实可套用的 DLC 选择差异。

## 修复

- 服务端拒绝世界准备时传递已经验证的管理员恢复能力，复用原有凭据授权覆盖流程。兼容性不符仍拒绝入服，不返回成功会话或殖民地状态，也不自动修改基线。提交：`5666aa5c`。
- 客户端在现有差异生成流程中标记实际的模组/DLC 选择变化，仅据此提供套用清单。版本、文件、协议和清单格式差异明确提示手动处理；未知问题不会自动获得套用能力，缺少服务端清单时也不能执行套用。
- 当时混合差异仍允许修复其中实际可套用的列表和配置；2026-10-24 按用户要求改为文件差异优先，见下文。
- 同步更新中、英、日、韩、俄五种提示，明确套用不会下载或替换游戏及模组文件。

## 验证

修复前，新增客户端测试在仅游戏版本变化时失败；新增 HTTP 测试在管理员被拒绝后未收到覆盖能力时失败。修复后针对性验证通过：

- 客户端 3 组：兼容性报告与恢复、覆盖协议、覆盖生命周期。包含四种区域文化、版本/格式/文件及组合变化、普通玩家与管理员、可修复与不可修复差异混合、缺失清单和服务端差异回退。
- 服务端 3 组：兼容摘要/详情交换、世界会话准备、世界准备独立模块。世界会话准备 114 个场景、独立模块 108 个场景。
- 新增 8 个 HTTP 恢复场景：完整清单/摘要两种请求 × 管理员/普通玩家/错误密码/已撤权账号。管理员不需要先成功入服即可覆盖过期基线，持久化后重新入服成功；其余账号不能覆盖，持久化基线不变。
- 五种语言 XML 解析和差异格式检查通过。

使用本机 1.7 运行程序集执行客户端单元测试；没有运行全量回归或实机界面像素验收。日志保留在本机 `LocalOnly/baseline-update-{client,server}-{before,after}.log`，不提交运行产物和个人数据。

## 部署影响

恢复管理员按钮需要更新**服务端**；仅更新客户端无法补回旧服务端漏传的能力标志。客户端更新则修正错误套用入口和提示。管理员确认当前游戏及模组版本作为新的服务器要求后，可通过原有覆盖按钮更新基线，再重新入服。此次代码修复没有替用户覆盖线上基线，也没有发布新构建。

## 2026-10-24：协议诊断与修复操作优先级

- 主菜单握手失败、世界会话准备被拒绝以及地图内登录被拒绝时，明确的协议不兼容均进入清单界面。概览显示客户端/服务器版本及拒绝原因；尚未取得服务器清单时明确标为未知，不显示“文件/配置一致”。协议不兼容不能用套用配置或覆盖基线绕过。
- HTTP 非成功状态中的结构化协议拒绝沿用统一解析，保留错误语义与已知服务器协议；不会按可重试网络错误循环重试，也不会使无关会话失效。普通 502/503/504 显示请求路径、本地版本和服务可用性提示。没有结构化证据时不把 HTTP 状态臆断为协议不兼容。
- 当前服务端的登录/世界准备协议拒绝仍返回 HTTP 200 和业务错误码，已补齐所需协议与客户端协议。用户当时的 503 来源尚未确定；这次修正错误展示与路由，不代表已确认其代理或服务器故障原因。
- 最终按用户指定顺序：模组列表和排序 → 文件哈希 → 配置文件。混合差异先允许套用模组列表；列表一致后，文件哈希、文件缺失、多余文件、Def 摘要、游戏版本等需要手动处理的差异阻止配置操作。模型和按钮采用同一规则。文件差异仍保留服务端已授权的管理员覆盖入口，协议不兼容仍先行拒绝。
- 验证通过：9 组客户端定向测试及服务端登录模块、世界会话准备、启动/元数据协议 3 组。覆盖结构化 400/409/503、普通/畸形 503、四种区域文化、缺失清单、旧请求失效和混合差异。未运行全量回归或实机界面验收。日志位于本机 `LocalOnly/ProtocolDiagnostics20261024/`。

### 管理员覆盖二次确认

此前两个覆盖入口仅在模组列表或顺序变化时确认，文件/配置变化会直接开始覆盖。现在清单界面和管理页统一通过同一个原版确认框：始终说明当前客户端的版本、文件、加载顺序和配置将成为服务器新要求，并影响其他玩家后续登录；列表/顺序差异追加专门提醒。取消不启动操作，确认仍复验原请求身份和权限，沿用原有一次性提交。

相关客户端 4 组测试通过：清单报告/确认流程、管理页、覆盖协议 120 场景、覆盖生命周期 1064 场景。新增确认测试覆盖相同/不同/未知列表、取消、确认、过期确认及重复回调；五种语言 XML 检查通过。日志为 `LocalOnly/ProtocolDiagnostics20261024/confirmation-tests.log`。

### 校验阶段顺序

完整清单先校验模组集合和声明的加载顺序，失败即停止后续比较；所有模组文件与 Def 摘要通过后才比较配置，避免某个模组的配置差异抢在另一个模组的文件差异之前。摘要交换复用相同列表校验，既有摘要哈希仍保持原格式；需要详情时，完整/选择性详情复用同一个分阶段比较过程。可选模组和纯翻译模组的原有许可规则保留。

客户端清单按 `LoadOrder` 排序展示与比较，而非采用 JSON 数组的物理顺序。列表套用移除隐含的配置写入和临时配置启用，只保存启用列表/顺序并重启；后续文件一致后再单独处理配置。已有详细差异仍可查看，操作和概览提示按上述顺序引导。

定向验证：客户端清单与恢复、摘要/详情契约、设置与配置套用 3 组通过，新增混合差异阶段矩阵覆盖四种区域文化和完整/选择性详情，实际配置文件验证列表套用不会写配置或启用 overlay。服务端握手模块、摘要/详情交换、登录模块、世界会话准备 4 组通过，日志为 `LocalOnly/ProtocolDiagnostics20261024/order-server-tests.log`；客户端日志为同目录 `order-tests.log`、`order-summary-tests.log`、`order-report-tests.log`。未运行全量回归。
