## 1. 事件读取身份与快照

三个读取协议增加会话令牌，客户端随请求传递。服务端复用恢复边界和殖民地会话认证，在读取/维护账本前验证权威快照；长轮询不持有变更锁等待，醒来后重新验证。登录、轮询和队列查询统一按当前殖民地过滤，避免旧殖民地条目混入详情批次。

验证：`EventReadHttpTests` 覆盖无令牌、无效令牌、冒用身份、错误殖民地、过期/空快照、正常投递、旧殖民地隔离，以及等待期间会话替换/快照推进。客户端 DTO 往返测试覆盖新增字段。完整网络回归和客户端 1.7 构建通过；存档测试继续验证暂缓决策后的投递基线。

## 2. 完整载荷与展示摘要

`PayloadSummary` 保留现有线协议名称，明确作为完整业务 JSON 使用。删除投递层的 4096 字符、2MB、3MB 硬截断；UI 自有的展示预览仍可截短。包上传与请求体原有准入限制继续负责输入约束，不在已接受事件的读取阶段损坏数据。

验证：`EventPayloadWireTests` 检查中文、ASCII、引号/换行/表情通知和超过旧阈值的交易、礼物、支援、袭击结算载荷，并经过 HTTP 外层序列化往返验证末尾字段。真实 HTTP 测试验证 800 字中文通知完整送达。

## 3. 礼物退回路由

退件工厂不再复制原收件人的地图。拒收入口在原子变更范围内，从发送者最新权威快照解析退回落点，并通过统一拒收计划传入内存、文件和 SQLite 后端；复用普通礼物的落点解析。重试保留已提交退件的路由与消费状态，避免搬家后重复拒收改写原记录。

验证：真实 HTTP 使用发送者 `Map_7`、接收者 `Map_9` 验证拒收后账本和下载详情均指向发送者。三种账本后端验证路由持久化和重新打开后的幂等重试。

## 4. 批量详情的原子状态变更

先验证所有事件可见性，再准备全部详情和状态变更，通过已有 `LedgerBatch` 一次发布投递、通知消费和终态清理。单条与批量投递/接受共享同一状态转换对象，三个后端仅负责持久化。缺失/不可见条目或序列化失败不会发布前半批；文件/SQLite 写入失败回滚整批。

验证：HTTP 混合通知、礼物、冲突事件与无效/不可见 ID，失败时账本完全不变；有效批次去重且返回清理前的终态详情。三种账本验证旧状态冲突，文件锁和 SQLite 中途故障验证内存与重启后的磁盘状态均未部分提交。

## 5. 类型化袭击结算识别

信件分类和结算内容展示复用 `RaidSettlementPayloadReader`，仅当袭击载荷的顶层 `Settlement` 对象非空才判定为结算。DTO 与解析器移出游戏 UI 文件，核心测试直接编译生产解析器。

验证：字段缺失、显式 null、正文同名字符串、嵌套同名字段、截断 JSON、空损失列表、Unicode 转义字段名、错误事件类型和实际损失内容。

## 6. 信件规则与实际客户端测试统一

删除仅由测试调用的共享信件投影及其五个配套模型，避免继续维护客户端不存在的按钮和不同的颜色规则。实际客户端的信件显示、动作资格、自动应用、载荷分类与信件类型规则集中到 `ClientEventLetterPolicy`；信件按钮构建、点击执行和自动处理共同调用。未知队列组使用固定标识，仅在展示时翻译。

原共享测试保留账本和队列语义断言，将 UI 断言迁移至 `EventLetterPolicyTests`，直接运行生产客户端代码及实际载荷解析器。覆盖普通/强制/退回礼物、全部交易交付/退款用途、临时/永久/返还支援、四类外交、通知级别与正文、普通袭击/空结算/结算/进攻方损失，以及全部队列分组、未知/本地化分组、定位和稍后按钮。四种文化环境重复验证，确保按钮生成与执行权限一致，终态不能重复操作。

验证：本地 RimWorld 1.7 程序集上的客户端 42 项测试通过，Events 52 项通过。原共享投影测试迁移到客户端，并非删除行为覆盖。
