## 修复：废弃后旧在线会话仍可保活

`AbandonPlayerColony` 成功后，原实现删除快照、写入墓碑并撤销认证令牌，但没有终止 `LoginSessionRegistry` 和在线连接。正常客户端收到成功响应后主动取消连接，掩盖了服务器清理不足。

独立端点复现保留原连接，结果为：`accepted=true`、`deleted=true`、`tokenValid=false`，但 `sessionValid=true`、`heartbeatAccepted=true`、`presenceStillOwned=true`、`rebuildSessionAccepted=false`。旧会话可以继续刷新并阻止同账户立即重建登录。复现输出保存在 `LocalOnly/account-session-probe.log`。

修复在持久化删除的应用阶段、原快照变更锁内，按用户和殖民地解析所属会话，复用 `EndSessionConnectionLocked` 终止会话、令牌和在线连接。旧殖民地删除重放不会选中另一个殖民地的新会话。修复后的同一复现中，旧会话/心跳/在线状态均为 false，新登录为 true，见 `LocalOnly/account-session-probe-fixed.log`。

`ColonyAbandonmentBaselineTests` 新增真实快照删除、原连接未主动断开时立即重建、旧令牌重复废弃拒绝、旧删除重放与迟到连接释放不影响新会话的回归。完整 Save 测试 135/135 通过，日志 `LocalOnly/account-save-tests-fixed.log`。其中原有删除中断恢复、迟到登记、登出授权和连接所有权用例一并通过。

## 服务端成就与排行榜

`AchievementLifecycleTests` 覆盖全部 11 个内置成就，在 en-US、zh-CN、fr-FR、tr-TR 下分别验证低于阈值、等于阈值、重复提交、更高值、随后低值与 SQLite 重开；最高值及其来源快照必须保留。累计指标另验证重复来源、零/负增量、九次到十次的阈值，以及同账户新殖民地从零开始。

使用 12 名具有真实快照的玩家验证前十截断、降序及同分时用户/殖民地 ordinal 排序、中文显示名、自己的成就查询、废弃后从榜单和定向查询隐藏、持久化重开后仍保留历史记录。此层直接准备指标与玩家数据，不代表所有 11 种成就在游戏中的触发链都经过实机验证。

## 实机覆盖与边界

测试经真实建档、业务操作和十秒废弃确认推进；显式夹具只补足邮费预算、设置资源存储区，以及通过 `Pawn.Kill` 制造雇佣兵死亡。没有直接写入成就、银行或事件账本。共用现有登录、商店、银行、交易、保存和重连助手；新增确认入口仍遵守原窗口倒计时。

| 阶段 | 断言 |
| --- | --- |
| 注册与建档 | 两个独立账户、共享世界、独立殖民地、初始快照、改密拒绝及成功；世界参数、难度、文化引用共用原矩阵 |
| 废弃前 | 十笔实际交易解锁成就，重复上传不重复计数；私聊已读、全局商店、联盟、双方未还贷款、普通玩家死亡赔偿及另一份活跃雇佣合同 |
| 废弃 | 取消确认无修改，确认等待十秒；删除快照和地点、写墓碑、清贷款/欠款、关闭合同、取消卖单及接单记录；另一玩家存档、物资、贷款和欠款保持不变 |
| 服主重建 | 原密码登录而非重新注册，新殖民地 ID，仅一个新地点；管理员身份与私聊保留，银行任务和雇佣不继承，旧联盟解除，全局商品与库存保持 |
| 成就再获得 | 新殖民地首笔交易不能继承旧十次进度，再达到十笔后独立解锁；旧历史仍在数据库，但不再出现在可见榜单/定向查询；当前榜单与账本一致、无重项 |
| 普通玩家重建 | 同样清理贷款、死亡赔偿、活跃佣兵和旧成就；密码、私聊保留且不获得管理员权限；随后存读档、退出、重连仍保持新殖民地 |

## 已确认的产品语义

- **账户保留**：离线密码、私聊历史、服务器管理员身份。废弃服主的殖民地不会使服务器失去管理员。
- **殖民地重置**：贷款和赔偿欠款、雇佣合同、本地银行任务、联盟、交易与当前可见成就。成就历史没有物理删除，新殖民地单独累计；旧殖民地从排行榜隐藏。
- **全局状态保留**：共享世界、商店商品及剩余库存、另一玩家的存档与资产。
- 因此，当前实现确实允许以永久丢弃整个殖民地为代价清除贷款/赔偿，且重建后成就重新计算。这里记录现有殖民地作用域规则，没有擅自改为账户终身债务或账户永久成就。

## 失败尝试与限制

所有失败运行保留，不计为通过。测试准备曾因邮费不足、补款不在存储区而停止；旧成就助手只按用户查找而误把两代记录当重复；接单断言曾误用业务 TradeId 而不是订单事件 ID。均修正测试条件/断言后重新执行完整场景，未放宽业务验收。

全 DLC 三次在用例开始前发生 `Internal CLR error (0x80131506)`，栈涉及 MonoMod 编译钩子与 Waylith 工作线程。诊断重试对启动器及其子进程设置 `DOTNET_PROCESSOR_COUNT=4`，此后进入业务用例；这只是测试环境限制，不能证明根因或未限制线程时的启动稳定性，未修改产品默认环境。环境记录保存在对应运行的 `execution-environment.json`。

尚未覆盖实机废弃响应丢失/进程硬杀、旧本地存档强行恢复、真实服务器进程重启时客户端自动恢复、废弃时仍在途的支援 pawn/袭击、全部成就的游戏内触发链与奖杯建造。现有服务端删除中断恢复和连接归属测试不能替代这些实机组合。`fullCoverage` 保持 false。
