## 场景与断言

- `stability-transfers-core` / `stability-transfers-dlc`：观察地图连续开关三次；远端地图销毁钢铁后，核对双方原地图的物品/建筑、观察方地图数和快照身份保持不变；有伤疤、非默认品质/耐久装备、关系和基因的 pawn 经支援接受、重复接受、提前返回、拒收返回、到期返回后保持状态；袭击战场产生损失后保存/重载、结算、重复结束及守方重连。
- `stability-items-core` / `stability-items-dlc`：六类复杂物品经真实交易撤单返还及空投成交，检查材质、品质、耐久、尸体污染、颜色、食材、腐烂和燃料。到货物品通过独立观察读数核对，而非重新调用产品序列化器作为期望值。
- `stability-support-permanent`：永久支援保持 pawn 状态、不建立临时到期分配，重复接受不复制 pawn。`stability-support-death`：通过原版死亡路径杀死已接收的临时支援，再让任务到期，核对本地任务清理、唯一死亡事件、发送方快照确认及重复接受不复活。
- `stability-shop-core` / `stability-shop-dlc`：遍历原商店编辑器的完整可选 Def 目录，逐项上架、实际购买；每批推进真实 tick 等待落地，检查库存、银币、材质、品质、耐久、基因、书籍研究/技能及武器/训练器特质。目录数量由加载的 Def 动态确定；未完成配置、被拒绝或异常均不算通过。
- `stability-shop-stress`：通过正式持久化 registry 注入 1,000、10,000、50,000 条商品；真实客户端接收完整目录并购买，另外执行 64 个并发 registry 调用竞争 20 件库存，复验幂等、买家历史及数据库重开。并发 registry 用例不是 64 个真实游戏客户端。
- `stability-shop-regression`：共用完整目录的测试实现，仅选择六种已复现问题相关商品，供改动后快速回归；报告使用独立的 `shop-selected-catalog` 用例，不计作完整目录验证。

所有夹具均为显式 `fixture` 命令或报告中的 volume fixture，要求回环测试服务器及 debug 能力；unsafe 反射控制仍关闭。伤疤/装备、下一 tick 到期、战场销毁及复杂物品创建不是玩家操作验收。实际流转、保存、支付与结算走正式逻辑。环境腐蚀通过只读伤害观察器记录，比较时仅扣除确实发生的 Deterioration 伤害，不能用通用耐久容差掩盖恢复丢失。

“完整商品目录”指当前加载组合下编辑器提供的全部 Def，各自使用一组有效的具体配置（合法材质、非默认品质/耐久、书籍内容、基因或武器特质）。它不代表所有材质 × 品质 × 基因 × 特质组合，也不验证购买后每个物品的全部使用行为。全 DLC 的目录包含 Core 商品，二者数量不能相加当作独立物品数。

全 DLC 目录采用四个互斥的显式样本（214 / 213 / 213 / 213），每组独立建立世界、枚举完整目录，再购买指定子集。汇总必须同时满足：四组观察到相同的 853 种 Def；购买结果无重复、无缺失且并集等于完整目录；每组最终报告通过、无未执行项。单个 `shop-selected-catalog` 通过不能代表完整目录通过。正式场景仍可使用 `stability-shop-dlc` 一次连续验证完整目录。

## 已复现并修复

1. **支援往返导致关系翻倍**：关系占位 pawn 再次打包时按接收方本地 ThingID 生成身份，返回后与原有恋人、父母、动物羁绊重复。统一 `PawnGlobalIdUtility.Build` 优先使用已标记的全局身份。提交 `a3ca94c5`；定向单元测试通过，真实全 DLC 提前/拒收/到期返回通过。
2. **品质提高时丢失耐久**：入站物品先按默认品质最大耐久裁剪，再设置最终品质。改为先设置品质，再按最终最大耐久裁剪。提交 `7b0c0300`；覆盖升级和降级两个方向的单元测试通过，Core 完整 397 种商品复验通过。
3. **空 minified 壳可上架并导致购买空引用，树木未包装**：可选目录误收录裸 `MinifiedThing` / `MinifiedTree`；购买时访问不存在的 InnerThing，且可能停在本地原子变更中。筛选排除裸壳，入站构造拒绝没有内部定义的壳；可搬运树木与建筑共享打包模板。提交 `bdeea508`；单元测试通过，Core 完整目录复验通过。
4. **带成瘾状态 pawn 的战斗存档重载报错**：既有缺失需求追踪器补丁只覆盖首次远程投影加载。保存后普通 Scribe 加载先恢复健康再构造需求，也会访问尚未赋值的 needs。补丁现在同时覆盖 `LoadingVars` 阶段，仍仅在 needs 缺失时介入，正常运行及已恢复 tracker 使用原逻辑。提交 `6aa3726a`；定向单元测试及全 DLC 22 项实测通过。
5. **复杂物品流转重置原版组件状态**：撤单实测中风衣颜色从 `(0.2,0.4,0.6)` 变成默认色；精致餐的人肉/土豆成分丢失、腐败进度从 12,000 回到新鲜状态；燃料炉 18.5 燃料清零。统一传输管线保存/恢复颜色、成分、腐败进度与燃料；浮点值使用不依赖区域格式的表示，字段先验证再应用，重复应用不累计燃料；旧载荷无这些字段时保持原行为。既有第三方 Scribe 回退选择不受这些通用字段影响。提交 `101a3667`；单元测试及 Core/全 DLC 各 17 项实测通过。
6. **打包目录与权威白名单不一致**：12 种 Core 树木在商店中可选，但被服务端当作未批准的打包对象拒绝。基线生成、商店、交易和管理员选择器现在共用 `IsPackableItemDef`，删除三处独立判断。提交 `cc0b2899`；单元测试与六商品实机回归通过。旧服务器需由管理员重新提交当前客户端的管理员数据基线，已有白名单不会凭客户端升级自动改写。
7. **死亡支援无法结束，死亡返回又被误当活人**：任务到期入口提前拒绝死亡 pawn；接通现有结束流程后，又发现接收方仅凭三个原因字符串识别死亡，将 `QuestExpired` 死亡返回判作不可恢复的活人载荷，最终取消事件。死亡分支复用统一快照确认/结束路径，服务器在返回引用中明确写入 `Dead=true`，客户端依据死亡状态处理并保留既有三类原因的旧记录兼容。提交 `2fcc52be`；客户端单元测试、存档/端点回归及实机 17 项通过，含发送方入档和结束后重复接受不复活。
8. **购买的人类胚胎丢失基因**：原编辑器允许给所有 `GeneSetHolderBase` 选择基因，恢复端却只处理 `Genepack` 和 `Xenogerm`，导致 `HumanEmbryo.GeneSet` 为空。统一补齐其他基因承载对象的恢复；先解析全部基因再替换，保留前两者的原版初始化流程。提交 `095b36ab`；未知基因及重复应用单元测试通过，五商品全 DLC 实机专项 15 项通过，含胚胎、基因包、异种胚芽、Odyssey 特殊武器及 Royalty 人格武器。

## 保留的失败及测试修正

- `StabilityTransfers/20261016-124537-724b2a96`：首版错误比较关系占位对象的完整姓名，而协议承诺 LabelShort；另一个 profile 使用了未安装的语言目录名。已修正测试，不算产品修复。
- `StabilityRound2/20261016-124920-4fd6abc4`：保留关系重复和商店耐久/空壳错误。Core 商店在空壳购买异常时中断，其余项目不能计入已购买。DLC 目录的旧版本运行在确认同类缺陷后停止，保留为失败，随后使用修复版本重新开始。
- `StabilityFixed/20261016-125715-619ac948`：Core 客户端在 hello 前发生 CLR `0x80131506`，栈包含 MonoMod JIT hook、ThreadLocal 与 Waylith WorkerLoop；`StabilityDeathFixed/20261016-133927-466b89d5` 与 `StabilityDlcCatalogLease/part-2/20261016-142843-624b44a8` 再次发生同类启动错误。均保留为失败，尚未定位根因，后续重跑通过不能消除这些记录。全 DLC 袭击另误用 100% 损失断言比较服务器默认 50% 损失上限，实际 62 件损失结算为 31 件，属于测试预期错误。专项场景现显式设置 100% 上限以检查精确损失。
- `StabilityStress/20261016-125447-7fdd08bd`：运行器构建失败后误启动旧二进制，压力用例未执行，最终报告正确判失败；不能引用其世界检查通过为压力证据。
- `StabilityExpanded` / `StabilityLoadFixed`：复杂物品夹具首轮选用不可搬运的火把、使用错误的大理石 Def，另一次未按交易规则给落地物品设置仓储区。改为可搬运燃料炉、`BlocksMarble` 及共用仓储操作后重跑；这些属于夹具修正。
- `StabilityItems/20261016-132018-43440262`：Core 与全 DLC 均独立复现颜色、食材、腐败和燃料丢失；原字段差异保存在 `trace.jsonl`。
- `StabilityCatalogFixed/20261016-130927-f111fac6`：Core 完整扫描发现 12 种树木上架拒绝及银币测试计账错误。银币既是支付手段又是商品，现单独落地核对，避免把同批其他购买扣款误判为丢失。对应旧 DLC 运行在确认同类问题后停止并保留失败。
- `StabilityDeath/20261016-133456-b47350e8`：死亡后到期分配一直保留；`StabilityDeathRetry/20261016-134026-f1a27e6a`：本地分配已清理，但发送方将死亡返回判作不可恢复，源/返回事件都变为 Cancelled。两个阶段分别保留。

- `StabilityDlcCatalogReady/part-1` / `part-2`：新增全目录预检后，测试错误地缓存了整轮商品对象引用；约五分钟后触发 RimTest 的 `stale_handle` 租期保护，两组各完成 80 种落地核对后失败。改为预检仅检查配置，购买和落地观察时重新取得对象引用；没有延长框架租期、增加隐式重试或把失效引用放行。
