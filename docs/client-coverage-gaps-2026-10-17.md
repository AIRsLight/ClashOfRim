# 客户端实机覆盖缺口与补测顺序

核对范围：当前 `Source/Client`、README 的行为约定、`Tools/RimTestScenarios.json` 与世界参数、流转、银行迁居、账户生命周期实测报告。这里的“未覆盖”表示没有找到对应的可执行实机场景和通过证据，不是静态行覆盖率，也不代表代码一定有缺陷。服务端单元/故障测试、商品能够购买、DLC 状态可以保存，均不能代替客户端实际使用该功能。

历史矩阵中的“尚未覆盖”表已经部分过时：复杂物品、支援永久/拒收/到期/死亡、两次逾期处罚、已有任务地点迁居、普通重力飞船起降、DLC 单独启用、废弃重建和排行榜已补测。以各专项报告及下表的具体剩余分支为准。

## 本批执行

新增 `offline-delivery-core`、`offline-delivery-all-dlc`，每场 19 项：14 项共有世界/难度/存读档/重连/错误门禁，加联盟、远行队与以下三个新用例。全 DLC 场使用中文 zh-CN / 英文 fr-FR。

| 用例 | 关键断言 |
| --- | --- |
| `gift-offline-deferred-accept` | 收方离线时礼物排队；登录下载、重复刷新、暂不操作后重连都不增加库存、不完成账本；接受后上传确认；再次登录及重复接受不重复到账 |
| `gift-offline-reject-return` | 发方先扣除远行队货物，退出后收方拒收；唯一返还事件离线排队；重复拒收不再建返还；发方登录后自动落货，家园与远行队库存守恒，再次登录不重复 |
| `notification-offline-policy` | 持久通知排队并在登录后确认；仅在线通知不向离线玩家建事件，重新登录及刷新也不得补发 |

复用原有礼物窗口、运输 gizmo、确认按钮、事件按钮、快照上传和退出/登录助手；新增测试未注入“成功”结果。运行证据同时保存服务器账本、客户端语义调用、运行日志、实际二进制哈希和 `DOTNET_PROCESSOR_COUNT`。这批是正常退出/重连，不是断网或硬杀测试；也不证明通知视觉呈现、不同地图 ID 返还定位或所有地图均卸载时的恢复。

本批发现并修复同一生命周期中的两处问题：

1. **未决定礼物在重连时被自动接受**：第二次登录后木材 300 → 303，玩家没有点击接受。下载详情将状态变成 `DeliveredToClient`，旧队列分类无条件把它交给自动应用路径。公共分类现在用 `EventSemanticClassifier.RequiresTargetDecision` 保留礼物、支援、外交的选择语义，已接受/不可拒收事件仍可自动恢复。
2. **稍后接受绑定过期快照**：修复分类后，上传新存档再登录接受，仍以首次下载时的快照校验，出现 `SnapshotBaseMismatch` 并留下“Gift landing”原子事务。详情重新下载现在在统一快照变更锁内，仅将尚未决定的已下载事件绑定到确实存在的当前权威快照。旧快照请求、发送方请求、已接受/自动/已完成事件不改基准；仍保留确认端的基准校验。

首轮测试时序错误（菜单已就绪但服务端异步登出未完成）另行修正为等待服务端离线，不列为产品缺陷。所有失败保留；详细运行与构建清单见 [验收 JSON](rimtest-offline-delivery-results-2026-10-17.json)。

最终 `offline-delivery-core` / `offline-delivery-all-dlc` 均 **19/19** 通过，位于 `G:/RimTestRuns/offline-delivery-r4/20261016-172255-77f3bbc9`。此前公共分类修复构建的 `gift-repeat-accept` **18/18**、`stability-transfers-core` **22/22** 也通过，包括支援提前返回/拒收/到期、复杂 pawn 状态与袭击损失存读档结算。合计 78 次调用、27 个不同用例；其中 38 次属于最终离线投递修复构建，不能描述成同一构建全矩阵通过。

最终组件回归：Events 53、Save 136、Client.Core 7、Client 41 个顶层测试通过，完整 HTTP/WebSocket/持久化网络 smoke 通过；冻结 1.6 源码 77、发布包 68 文件哈希通过。完整脚本曾因漏传客户端程序集路径、并行重建正在运行的 Save.Tests 导致 Windows 文件锁而失败，未算通过；最终逐组件执行记录保留在验收 JSON 中。
